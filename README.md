# Azure Retail Analytics Data Pipeline

An end-to-end Azure data engineering pipeline for ingesting retail transaction data, storing it in Azure Data Lake Storage (ADLS), transforming and validating it in Databricks using PySpark, and generating analytics-ready business metrics using SQL.

## Architecture

```text
HTTP REST API (JSON)
        |
        v
Azure Data Factory
        |
        v
Azure Data Lake Storage (ADLS Gen2)
        |
        |  Bronze - Raw Data
        v
Databricks
        |
        |  PySpark transformations
        |  Data quality validation
        v
Silver - Cleaned & Standardized Data
        |
        |  SQL analytics
        v
Gold - Business Analytics
```

## Project Overview

This project demonstrates a cloud-based retail data pipeline using the **Medallion Architecture (Bronze → Silver → Gold)**.

The pipeline:

1. Extracts retail transaction data from an HTTP REST API using **Azure Data Factory**.
2. Stores the raw data in **Azure Data Lake Storage Gen2 (ADLS Gen2)**.
3. Loads the raw Parquet data into **Azure Databricks**.
4. Applies data cleaning, standardization, validation, and deduplication using **PySpark**.
5. Stores the transformed Silver dataset back in ADLS as Parquet.
6. Registers the Silver dataset as a temporary view in Databricks.
7. Uses **Spark SQL** to generate business metrics and analytics from the cleaned data.

## Data Flow

### 1. Data Ingestion – Azure Data Factory

Azure Data Factory is used to extract retail transaction data from an HTTP REST API in JSON format.

The extracted data is ingested into the Bronze area of ADLS Gen2, providing a raw copy of the source data for downstream processing.

```text
REST API → Azure Data Factory → ADLS Gen2 Bronze
```

### 2. Bronze Layer – Raw Data

The Bronze layer contains the raw transaction data stored in Parquet format.

The Databricks notebook reads the raw Parquet files from the mounted storage location without applying transformations.

Example source fields include:

- `TransactionID`
- `CustomerID`
- `TransactionDate`
- `Quantity`
- `Amount`
- `Discount`
- `PaymentType`
- `StoreRegion`
- `DeviceUsed`
- `StoreLocation`
- `CustomerLoyaltyLevel`
- `ProductCategory`

### 3. Silver Layer – Data Cleaning & Transformation

The Silver layer prepares the raw data for reliable analytics.

The following transformations are implemented using PySpark:

#### Null Handling

Filters out records where critical fields are missing:

- `TransactionID`
- `CustomerID`
- `TransactionDate`

#### Text Standardization

Standardizes selected text fields by trimming whitespace and converting values to uppercase:

- `PaymentType`
- `StoreRegion`
- `DeviceUsed`

#### Data Type Casting

The pipeline converts columns to appropriate data types:

- `TransactionDate` → `timestamp`
- `Quantity` → `integer`
- `Amount` → `float`
- `Discount` → `float`

#### Business Rule Validation

Invalid transactions are filtered based on business rules:

- `Quantity > 0`
- `Amount > 0`
- `Discount <= Amount`

#### Deduplication

Duplicate transactions are removed using `TransactionID` as the deduplication key.

The cleaned Silver dataset is then written to ADLS in Parquet format.

```text
Bronze Data
    |
    +--> Null handling
    |
    +--> Text standardization
    |
    +--> Data type casting
    |
    +--> Business rule validation
    |
    +--> Deduplication
    |
    v
Silver Dataset (Parquet)
```

## Gold Layer – Business Analytics

The cleaned Silver dataset is loaded into Databricks and registered as a temporary view named `retail_data`.

Spark SQL is then used to perform analytical aggregations and generate business metrics.

### Analytics Included

#### Daily Revenue & Transaction Trends

Analyzes:

- Total revenue per day
- Number of unique transactions per day

#### Revenue by Payment Type

Analyzes total revenue generated by different payment methods.

#### Store Performance

Analyzes total revenue by store location.

#### Customer Loyalty Impact

Analyzes revenue contribution across different customer loyalty levels.

#### Product Category Sales

Analyzes total revenue generated by each product category.

#### Regional Performance

Analyzes regional performance using:

- Total revenue
- Total transactions
- Unique customers

## Medallion Architecture

| Layer | Purpose | Technology / Format |
|---|---|---|
| Bronze | Raw ingested transaction data | ADLS Gen2 / Parquet |
| Silver | Cleaned, validated, standardized data | Databricks / PySpark / Parquet |
| Gold | Business analytics and KPIs | Databricks / Spark SQL |

## Data Quality Checks

The pipeline performs several data quality operations before analytics:

- Missing critical field validation
- Text standardization
- Data type validation through casting
- Positive quantity validation
- Positive amount validation
- Discount-to-amount validation
- Duplicate transaction removal

These checks help ensure that only cleaned and validated records are used for downstream analytics.
